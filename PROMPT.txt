做一个可独立部署的圆管 Darcy 摩阻系数核算服务，让上游把流动工况交给它，按区制算出摩阻系数，并在湍流区把隐式残差压到钉死容差以内；需要时再给出沿程压降。这是一个纯服务端的水力计算组件，不涉及管网调度、前端页面或账户体系。

区制与摩阻：调用方给出雷诺数与相对粗糙度。雷诺数小于 2300 时走层流闭式，摩阻系数等于 64 除以雷诺数，不得套用湍流隐式方程。雷诺数落在 2300 到 4000（不含 4000）的过渡区时，必须标明该区未建模并返回可区分的结果类型，不得用层流或湍流公式充数。雷诺数大于等于 4000 时走湍流，摩阻系数必须满足以十为底的残差落在钉死容差内：一除以摩阻系数的平方根，与负二倍的常用对数（相对粗糙度除以 3.7，再加上 2.51 除以雷诺数与摩阻系数平方根的积）之差足够小。求根不收敛要返回错误，而不是交出一个残差很大的数。对数必须是以十为底。雷诺数非正、相对粗糙度为负或大于等于 1，都要在计算前返回带说明的结构化错误。

压降：在已得到合法摩阻系数的前提下，若调用方同时给出管长、管内径、平均流速与流体密度，还要给出沿程压降；压降必须与摩阻系数、管长成正比，与流速平方成正比，与管内径成反比。缺这些可选字段时只返回摩阻系数与区制，不报错。管长、管内径、流速、密度若出现但取非正值，要在计算压降前拒绝。

必须守住的行为：层流区把雷诺数加倍，摩阻系数必须减半。只把相对粗糙度加大、同一湍流雷诺数下摩阻系数必须升高。光滑管（相对粗糙度为零）且雷诺数很大时，摩阻系数仍随雷诺数升高而下降，不得变成与雷诺数无关的常数。同一组湍流参数下，把摩阻系数代回残差定义，残差必须落在容差内。管长加倍则压降加倍；流速加倍则压降变为四倍。请预置一个可直接调用的算例：商用钢管量级的相对粗糙度、雷诺数十万，摩阻系数应落在 0.018 量级。

输入与异常：缺字段、非数值、非有限值、把层流雷诺数却强制要求湍流结果等矛盾请求，都要返回带说明的可读错误，而不是算出一个看似正常其实错误的数，也不能直接崩溃。批量核算中某一组非法时，要指出是第几组、哪个参数的问题，其余各组照常返回结果。

服务能力：除单次摩阻核算外，支持按雷诺数网格生成同一相对粗糙度下的摩阻系数序列，支持一次提交多组工况的批量核算，并把每次核算请求与结果持久化保存，供之后按条件查询历史记录。对外提供摩阻核算接口、压降接口、雷诺数序列接口、批量接口、历史查询接口，以及一个回显区制阈值与残差容差配置的查询接口。服务需暴露基本运行状态供监控采集，且并发处理多请求时结果互不干扰、历史记录不错乱。

技术上用 Python 实现，基于 FastAPI 提供 HTTP 服务，持久化用数据库，提供 Docker Compose 一键构建并启动服务与其依赖。代码请合理拆分为多个模块/文件，区制判定、湍流求根、压降、输入校验与持久化不要堆在同一个文件里。附带能验证上述核算规则的自动化测试，覆盖层流摩阻等于 64 除以雷诺数、层流雷诺数加倍则摩阻减半、湍流残差闭合、相对粗糙度加大则湍流摩阻升高、光滑管高雷诺数下摩阻仍随雷诺数下降、过渡区标明未建模、管长与流速对压降的比例关系、非法参数被拒、批量部分失败其余成功、历史持久化正确、以及并发多请求互不串扰。
